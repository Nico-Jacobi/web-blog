### Schritt 4: `model/trip.dart` migrieren (7 Aufrufe — TripMethod Labels)

`trip.dart` ist ein Datenmodell und hat keinen `BuildContext`. Die `tripMethod`-Labels können daher nicht direkt über `AppLocalizations.of(context)` aufgelöst werden.

**Lösung:** Labels aus dem Model entfernen, stattdessen in der UI über `AppLocalizations` auflösen.

**Aktuell:** Das Model gibt `AppStrings.tripMethodCar` etc. zurück.

**Neu:** Das Model gibt einen unveränderlichen Enum-Wert oder String-Key zurück (`'car'`, `'boat'` etc.), die UI übersetzt beim Rendern:

```dart
// In trip.dart — tripMethod-Objekt nur noch mit id und icon, kein Label:
// Vorher:
TripMethod(id: 'car', label: AppStrings.tripMethod_car, icon: Icons.directions_car)

// Nachher:
TripMethod(id: 'car', icon: Icons.directions_car)
// label-Feld entfernen oder auf String-Key setzen (kein AppStrings mehr)
```

**In allen Stellen die `method.label` rendern** (Pages/Widgets, aus Plan 04.1 ggf. schon angepasst):
```dart
// Statt method.label:
_getTripMethodLabel(context, method.id)

// Hilfsmethode in der Widget-Datei:
String _getTripMethodLabel(BuildContext context, String id) {
  final l10n = AppLocalizations.of(context)!;
  switch (id) {
    case 'boat':  return l10n.tripMethodBoat;
    case 'car':   return l10n.tripMethodCar;
    case 'rv':    return l10n.tripMethodRv;
    case 'plane': return l10n.tripMethodPlane;
    case 'foot':  return l10n.tripMethodFoot;
    case 'misc':  return l10n.tripMethodMisc;
    case 'bus':   return l10n.tripMethodBus;
    default:      return id;
  }
}
```

**Hinweis:** Prüfen wo `method.label` aktuell verwendet wird (manage_points_page, create_point_page, travel_method_dialog) und dort die Hilfsmethode einsetzen.

### Schritt 5: `main.dart` — Notification-Strings migrieren (6 hardcoded Strings)

Die 6 Spaß-Nachrichten (Zeilen 239–244) laufen im Workmanager-`callbackDispatcher` — einem eigenen Dart-Isolate ohne Flutter-Framework-Initialisierung. `AppLocalizations` ist dort **nicht verfügbar** (kein `BuildContext`, kein Widget-Tree).

**Lösung:** SharedPreferences direkt lesen, dann per einfachem `switch` die passenden Strings aus statischen Maps wählen — kein `AppLocalizations` nötig:

```dart
import 'package:shared_preferences/shared_preferences.dart';
import 'dart:math';

// In der Background-Worker-Funktion:
Future<String> _getRandomSyncMessage() async {
  final prefs = await SharedPreferences.getInstance();
  final langCode = prefs.getString('app_language') ?? 'de';

  const messagesDE = [
    'Alle Kängurus wurden erfolgreich durchs Kabel geschubst.',
    'Deine Koalas sind sicher im Cloud-Eukalyptus gelandet.',
    'Krokodile abgewehrt, Daten erfolgreich hochgeladen.',
    'Daten-Roadtrip beendet. Alles sicher verstaut!',
    'Wombats haben deine Dateien artgerecht vergraben.',
    'Die Emus haben die Daten nach Hause gebracht.',
  ];
  const messagesEN = [
    'All kangaroos successfully pushed through the cable.',
    'Your koalas have safely landed in the cloud eucalyptus.',
    'Crocodiles repelled, data successfully uploaded.',
    'Data road trip complete. Everything stored safely!',
    'Wombats have buried your files in their natural habitat.',
    'The emus have brought the data home.',
  ];

  final messages = langCode == 'en' ? messagesEN : messagesDE;
  return messages[Random().nextInt(messages.length)];
}
```

**Notification-Channel-Namen** (`'Sync Notifications'`, `'Notifies when sync completes'`) sind technische Strings für Android-System-UI und bleiben auf Englisch.
